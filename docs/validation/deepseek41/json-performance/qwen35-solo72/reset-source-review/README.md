# Qwen3.5 cache reset source assessment

The reviewed reset path is inherited, with no demonstrated new correctness defect. The bodies of `EnsureOwnership`, `ResetKVCacheCore`, `ResetCacheTensor`, `InvalidateTensorDeviceCache`, and `ResetGdnLayerCache` are byte-identical to HEAD `04a5faa9e641fc0b06de661be1191afbc6edaf50`. The complete Qwen3.5 model/GDN/holder files, GGML Fill implementation, native core, and Qwen3.5 decode/verify/arena sources are also unchanged. `sources.json` records whole-file and method-body hashes. The changed portions of ModelBase concern only V4.1 tokenizer BOS and placement descriptions; they do not modify the reviewed reset logic. This is source evidence, not proof that different assemblies always receive identical JIT code or scheduling.

The sampled method `InvalidateTensorDeviceCache` directly obtains the storage pointer and calls the native invalidation wrapper; it does not perform reflection. Reflection frames in other reset samples are under the registered `Ops.Fill` path. See [ModelBase.cs:1964](/Users/zhongkaifu/work/TensorSharp/TensorSharp.Models/ModelBase.cs:1964) and [GgmlBasicOps.cs:51](/Users/zhongkaifu/work/TensorSharp/TensorSharp.Backends.GGML/GgmlBasicOps.cs:51).

On a new solo sequence, [EnsureOwnership](/Users/zhongkaifu/work/TensorSharp/TensorSharp.Runtime/Scheduling/BatchExecutor.cs:3104) calls model reset. [Qwen35Model.ResetKVCacheCore](/Users/zhongkaifu/work/TensorSharp/TensorSharp.Models/Models/Qwen35/Qwen35Model.cs:1309) intentionally discards dirty device state, resets decode/verify bindings, walks all layers, and resets the logical length. The observed checkpoint has six attention and 18 recurrent layers. Thus this source walk invokes 12 attention K/V invalidations per reset; the trace does not independently count every native call.

For GGML CUDA, [ResetCacheTensor](/Users/zhongkaifu/work/TensorSharp/TensorSharp.Models/ModelBase.cs:811) skips host zero-fill but still evicts the device copy. [Native invalidation](/Users/zhongkaifu/work/TensorSharp/TensorSharp.GGML.Native/ggml_ops_core.cpp:1208) performs expected constant-time unordered-map lookups under rank cache locks, removes residency bookkeeping, and frees a resident buffer. The CUDA buffer destructor calls `cudaFree` ([ggml-cuda.cu:736](/Users/zhongkaifu/work/TensorSharp/ExternalProjects/ggml/src/ggml-cuda/ggml-cuda.cu:736)). This establishes an allocator/free boundary, not measured time spent in CUDA or an observed synchronization duration. The exported invalidator also visits model coherence hooks and drops captured graphs when a buffer was freed ([ggml_ops_core.cpp:3472](/Users/zhongkaifu/work/TensorSharp/TensorSharp.GGML.Native/ggml_ops_core.cpp:3472)). Qwen3.5's solo graph pool has eight entries; verify has 16 entries and checks recorded host-binding lists. This is bounded pool work, not a full weight-tensor scan. After the initial graph teardown, later K/V invalidations can revisit empty pools, which is repeated bookkeeping but not repeated destruction of the same graph.

Next prefill [binds the full-capacity K/V tensors](/Users/zhongkaifu/work/TensorSharp/TensorSharp.GGML.Native/ggml_ops_qwen35_verify.cpp:1758). A cache miss allocates a resident copy with `needs_upload=true`, then [queues/uploads its full byte extent](/Users/zhongkaifu/work/TensorSharp/TensorSharp.GGML.Native/ggml_ops_qwen35_verify.cpp:1690). For this checkpoint's six attention layers, two KV heads, 256 head width and F16 cache, both K/V together require `12,288 × cache_capacity_tokens` bytes if all 12 resident copies were invalidated. Actual retained capacity is not established by the sampled stacks, so this formula is not an observed transfer count.

There is a concrete opportunity to investigate avoiding attention copy eviction during a logical CUDA reset: host bytes are unchanged, written rows are overwritten, and reads are mask-bounded. The source already uses that rule for Metal/Vulkan resets and CUDA holder reuse. It does not follow that deleting the invalidation call is proven safe. The existing teardown protects captured nodes when buffers move, and reset/reseed logic must preserve the authority of attention and recurrent caches. A candidate would need independent proofs for stale-prefix isolation, new and reused requests, chunked prefill, concurrent holders, capacity growth/pointer changes, failure recovery, and persistent graph replay. The existing source is internally explicit about its current eviction contract; no production patch was made.

Recurrent state must actually be cleared before an unrelated request. [ResetGdnLayerCache](/Users/zhongkaifu/work/TensorSharp/TensorSharp.Models/Models/Qwen35/Qwen35Model.GatedDeltaNet.cs:510) clears convolution arrays and fills each F32 delta-state tensor. For the observed geometry this writes 18 MiB of delta state plus 1,327,104 bytes of convolution state. The F32 [GGML Fill path](/Users/zhongkaifu/work/TensorSharp/TensorSharp.Backends.GGML/GgmlBasicOps.cs:122) uses `TensorIterState` and a scalar element loop; this is linear in state elements, with 4,718,592 delta-state iterations. The same implementation serves strided tensors, so a future contiguous zero-fill fast path would need explicit layout and value controls. This is inherited work and a bounded optimization candidate, not evidence of an introduced regression.

No inference, build, VM activity, or production source edits were performed for this assessment. The profiled reset spans remain sampled residence intervals that can include waiting; they must not be presented as exclusive CPU durations. The requested uninstrumented controlled run remains the next evidence step.
